Folded Paper Engine Guide
Blender → Godot workflows without the guesswork

This is the companion to the Blender and Godot add-on docs. It explains the pieces of Folded Paper Engine that are easy to miss, with concrete steps you can follow while building a small adventure.

Before you start

  • Install the Blender add-on and the Godot add-on first.
  • Keep Custom Properties enabled in your Blender glTF export so metadata makes it into Godot.
  • Add a FoldedPaperEngine node to your Godot scene and point its Path property at your exported GLB/GLTF.

Core gameplay setup

Player and NPCs

  1. Select a mesh in Blender and open the Folded Paper Engine panel (N → Item tab).
  2. Check Player to get the first-person controller, camera, and input bindings on import to Godot. Size the mesh to roughly 1m tall.
  3. For non-player characters, check Character. They import without the player camera so you can attach conversations, animations, or custom scripts in Godot.

Physics objects

  1. Pick meshes that should move (crates, debris) and enable Physics in the panel.
  2. Apply scale/rotation in Blender (Ctrl + A) before export to prevent offset or jittery collisions in Godot.
  3. Leave the toggle off for static floors and walls. If you prefer, append -col to the name of static meshes to let Godot create collision shapes automatically.

Holdable items & inventory

  1. Tag a mesh as Holdable Item to make it pick-up ready.
  2. Set its slot/size options so the player inventory can enforce limits.
  3. In Godot, the player can swap or drop items using the built-in Inventory script. Add your own UI on top, or surface the included item prompts in your HUD.

Speakers for dialogue and audio

  1. Enable Speaker on an NPC or scene prop to mark it as a dialogue participant and/or a 3D audio source.
  2. Provide a voice line ID or audio clip name so the Godot importer hooks up an AudioStreamPlayer3D.
  3. Combine with the conversation system (below) to attach branching dialogue without extra wiring.

Events and interactions

Triggers (interaction zones)

  1. Create an empty or simple mesh in Blender and enable Trigger.
  2. Resize it to cover the interaction volume (door sensor, puzzle pad, cutscene area).
  3. Optionally assign a trigger group to listen for multiple zones together.
  4. In Godot, connect the trigger to commands (below) or your own scripts to open doors, start dialogue, or award items.

Frame events on animations

  1. While editing an animation in Blender, add Frame Events in the Folded Paper Engine panel on the action.
  2. Name the event and pick the frame where it should fire.
  3. After import, the Godot AnimationPlayer will emit callbacks at those frames—use them to play sounds, unlock doors, or spawn effects.

Command system

  1. Use commands when you want to chain logic without writing new scripts.
  2. Attach commands to triggers, frame events, or UI interactions to do things like start conversations, toggle visibility, or load the next level.
  3. For custom logic, pair a command with Script Path (see Extensibility) so your GDScript runs at the right moment.

Level flow and scene metadata

Load the next level

  1. Pick a doorway or exit mesh in Blender and set its Load Level target to another GLB/GLTF path.
  2. Combine with a trigger so the new level loads when the player enters the zone or interacts.
  3. In Godot, the FoldedPaperEngine node will handle the transition and keep your player controller alive between scenes.

Sub-scenes and modular spaces

  1. Use Sub Scene to place a placeholder mesh that points to another scene file.
  2. Ideal for streaming interiors or reusable rooms; the importer swaps the placeholder with the referenced content.
  3. Keep origins aligned so the sub-scene drops into the right spot.

Environment settings

  1. Set Sky Color (and other environment props) in Blender so Godot picks them up on import.
  2. Assign Background Music to give the level a looping track without extra nodes.
  3. If your project needs altered gravity, look for the gravity settings in the panel so they come through with the level.

Water and reflective materials

  1. Mark surfaces that should use the engine water shader with the provided material toggle.
  2. Use the reflective/shiny toggle for mirrors or polished floors; replace materials in Godot if you need a custom shader.

User interface

Crosshair and cursor

  1. FPE ships with a default crosshair. Use the UI cursor options in the panel to swap the graphic or turn it off.
  2. When showing menus, unlock the mouse with the add-on’s cursor toggle so players can click UI without losing first-person controls when they resume.

HUD and UI elements

  1. Mark meshes as UI Element to render them as screen-space overlays (great for health bars, prompts, or icons).
  2. Parent HUD elements to the camera in Blender if you want them to follow the view; the importer keeps that relationship intact.

Options and pause menu

  1. Wire your pause or options UI to the same cursor toggle above.
  2. Bind the pause action in Godot’s input map (e.g., Esc) to display your menu and release the mouse, then hide it and lock the mouse again when resuming.

Conversations

  1. Pair a Speaker NPC with conversation data (lines, replies, comments) using the panel fields.
  2. Start conversations from triggers or commands—common patterns include talking when the player looks at an NPC or enters a dialogue zone.
  3. Use replies to build branches; the UI provided by FPE will list choices automatically.

Extensibility and advanced workflows

Script path

  1. Set Script Path on any object when you need custom behavior beyond the built-ins.
  2. Point to a GDScript relative to your Godot project (for example, res://scripts/door_controller.gd).
  3. Combine with triggers, frame events, or commands to call into your script at the right time.

Groups and tags

  1. Assign groups in Blender so objects arrive in Godot already organized (e.g., Enemies, Interactables).
  2. Use get_nodes_in_group or signals in Godot to manipulate whole categories without extra setup.

Material replacement

  1. Use the material replacement options to swap placeholder Blender materials with Godot materials on import.
  2. Great for pairing simple authoring materials with more advanced Godot shaders (PBR, reflective, water, etc.).

Troubleshooting checklist

  • Player too small/large or floating: apply transforms in Blender and keep approximate real-world scale (1 unit = 1 meter).
  • Missing metadata in Godot: verify Custom Properties was checked during glTF export and the Godot plug-in is enabled.
  • Triggers not firing: confirm the trigger volume surrounds the player path and that the command or script attached to it is assigned.
  • Animation events not running: ensure the frame event names are unique per action and re-export after editing the animation.
  • Audio not playing: double-check the Speaker’s audio clip name/ID matches a file available in your Godot project.
